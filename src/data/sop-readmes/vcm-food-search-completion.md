## 一、输入与处理口径确认

这一阶段对应流程图第一行，用于确认原始数据、语言口径和运行基础。

### 原始搜索数据

清洗脚本读取项目目录下的：

```text
raw_data.xlsx
```

该路径在 `vcm_food_clean.py` 中基于脚本所在目录计算，便于整个项目文件夹迁移给其他人使用。

原始表需要包含：

- `content`：原始搜索词或食物名称
- `lang`：原始数据携带的语言值

处理时会保留原始统计字段，并在后续追加结构化字段。

### 语言白名单

语言集合读取自：

```text
lang.xlsx
```

脚本会将原始数据的 `lang` 字段映射到 `lang.xlsx` 中允许的语言值。

当前核心映射规则：

- 原始 `lang` 为 `en_TH` 或 `en-TH` 时，输出 `th`
- 原始 `lang` 为 `zh-CN` 或 `zh-MY` 时，输出 `zh-cn`
- 其他 `zh` 开头语言输出 `zh`
- 其他语言取前两个字母后与 `lang.xlsx` 匹配
- 匹配不到允许语言时，删除该条记录

### 运行配置

清洗脚本使用 Python 本地执行。

核心输入和输出路径：

```text
raw_data.xlsx
lang.xlsx
vcm_food_clean.csv
```

可选联网和 LLM 配置来自：

```text
account.yaml
```

`account.yaml` 属于本地私密配置，只用于当前机器运行，不应放入公开交付材料。

### 过滤规则

进入正式清洗前会跳过明显不应进入食物库的数据。

跳过规则包括：

- `content` 为空
- `content` 等于 `未知`
- `content` 与食物或品牌无关，例如 `21世紀`
- 源语言无法映射到 `lang.xlsx`

## 二、食物清洗、翻译与结构化主链路

这一阶段对应流程图第二行，是 `vcm_food_clean.py` 的核心处理链路。

### 逐行读取

脚本逐行读取原始数据，并标准化 `content`。

主要处理：

- 清理前后空白
- 去掉食物数量，例如将 `2个水煮蛋` 处理为 `水煮蛋`
- 保留可用于分析的原始字段

### 语言映射

输出字段 `lang` 不再重新猜测为主，而是优先基于原始数据自带的 `lang` 字段映射。

该字段同时约束后续字段语言：

- `food_name` 必须使用 `lang` 对应语言
- `brand` 必须使用 `lang` 对应语言
- `unit` 必须使用 `lang` 对应语言
- `trans` 固定为简体中文释义

### 品牌识别

脚本会根据 `content` 判断是否存在品牌。

识别来源：

- 本地品牌别名词典
- 明确产品规则，例如麦乐鸡、全家茶叶蛋
- 联网搜索结果和 LLM 辅助判断
- 非品牌词排除表，例如普通食物词、酒类名、蛋白质等

`brand` 字段填写规则：

- 如果识别到品牌，填入该语言下最标准、最常见的品牌写法
- 同一种语言下同一品牌只保留一种写法
- 如果没有识别到品牌，则置空

### 食物名生成

`food_name` 字段必须是具体食物名称，不能只有品牌名。

生成规则：

- 如果 `content` 是普通食物，直接清洗为该语言下的具体食物名
- 如果 `content` 包含品牌和食物，输出格式为 `品牌名, 食物名`
- 如果 `content` 只有品牌名，选择该品牌下具体、较短、常见的招牌食物
- 如果模型返回结果语言不符合 `lang`，使用本地规则修复
- 对繁体中文内容保持繁体，不自动转成简体

品牌食物格式示例：

```text
KFC, Biscuit
麥當勞, 麥樂雞
全家, 茶葉蛋
丸亀製麺, うどん
```

### 中文释义

`trans` 字段填写 `food_name` 的简体中文翻译或释义。

处理原则：

- `trans` 不得为空
- 品牌食物会翻译为简体中文组合结果
- 日语、泰语、意大利语等非中文内容优先使用本地词典或联网翻译兜底
- 如果联网失败，脚本会回退到本地可解释结果，避免中断

### 单位与数量

脚本根据 `content` 和 `food_name` 推断最合适的 `unit`。

单位规则：

- 鸡蛋、水果等按“个”类单位处理
- 牛奶、咖啡、茶、果汁、拿铁等饮品按“杯”类单位处理
- 麦乐鸡、薯条、汉堡、饭、面、寿司等按“份”类单位处理
- 无法判断时填入 `g`

`unit` 需要按 `lang` 本地化；`g` 保持英文。

`amount` 规则：

- 克类单位，包括 `g` 及其他语言中“克”的写法，填 `100`
- 份、个、杯等非克单位，填 `1`

### 联网兜底与异常处理

当本地规则无法稳定判断品牌、食物或翻译时，脚本可使用联网搜索和 LLM 结果辅助清洗。

异常处理原则：

- 网络请求超时或连接重置时不让脚本崩溃
- LLM 配置缺失时回退本地规则
- 搜索或模型结果只作为辅助，最终仍需经过语言一致性、品牌格式和非空规则校验

### 质量收口

写出 CSV 前会执行最终修正。

重点修正：

- 清理 `品牌, , 食物` 这类多逗号结果
- 避免 `food_name` 只有品牌名
- 避免品牌或食物名重复出现
- 标准化同语言下品牌写法
- 按 `lang + brand + food_name` 去重，重复记录只保留第一条

## 三、清洗结果、营养估算与交付验收

这一阶段对应流程图第三行，用于生成最终可交付文件。

### 清洗 CSV

运行 `vcm_food_clean.py` 后生成：

```text
vcm_food_clean.csv
```

该文件包含原始字段和追加字段：

- `food_name`
- `trans`
- `lang`
- `brand`
- `unit`
- `amount`

运行时终端会显示关键字段，便于人工抽查：

```text
content
food_name
trans
lang
brand
unit
```

### 营养估算

营养脚本读取：

```text
vcm_food_clean.csv
```

并根据以下字段估算营养：

- `food_name`
- `unit`
- `amount`
- `trans`

估算逻辑：

- 匹配脚本内置的每 100g 营养档案
- 根据单位换算为当前数量下的营养值
- 无法识别时使用通用食物 profile
- 营养字段只输出纯数字，不带单位
- 小数四舍五入保留一位
- `calories(kcal)` 如有小数则四舍五入为整数
- 营养值为 `0` 时输出为空

### Excel 分片

运行 `vcm_food_nutri.py` 后输出：

```text
vcm_food_nutri_part1.xlsx
vcm_food_nutri_part2.xlsx
...
```

分片规则：

- 每 180 条数据输出一个 xlsx 文件
- 每个 xlsx 文件都包含表头
- 字段顺序以 `food_name`、`brand`、`lang`、`unit`、`amount` 开头
- 营养字段追加在后续列中

### 验收复核

交付前建议按流程图逐项检查。

清洗结果验收：

- `vcm_food_clean.csv` 已生成
- `food_name` 不为空
- `food_name` 不是单独品牌名
- `food_name` 与 `lang` 语言一致
- `brand` 与 `lang` 语言一致
- `trans` 不为空且为简体中文
- `unit` 不为空且与 `lang` 语言一致
- 重复的同语言、同品牌、同食物记录已删除

营养结果验收：

- 已生成 `vcm_food_nutri_part*.xlsx`
- 每个文件最多 180 条数据
- 每个文件都有表头
- `calories(kcal)` 为整数
- 其他营养字段最多保留一位小数
- 0 值营养字段为空

## 后续扩展方向

### 增加品牌与食物规则

当人工复核发现新品牌或误判时，优先补充：

- 品牌别名
- 标准品牌写法
- 品牌招牌食物
- 普通食物词排除规则

### 固化回归样例

建议从原始数据中抽取覆盖多语言、品牌、普通食物、数量、单位、去重的样例，形成可重复测试。

重点样例：

- 繁体中文食物
- 简体中文食物
- 日语品牌和食物
- 泰语食物
- 英语或欧洲语言水果、饮品
- 品牌名-only 输入
- 食物名-only 但可明确归属品牌的输入

### 优化营养档案

当前营养结果是估算值，后续可以继续扩展：

- 常见品牌快餐 profile
- 饮品 profile
- 米饭、面食、火锅、寿司等地区性食物 profile
- 更精细的单位重量映射

所有营养扩展都应保持字段纯数字输出，并保留分片交付规则。
