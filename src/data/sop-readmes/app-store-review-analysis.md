## 一、输入与口径确认

这一阶段对应流程图第一行，用于确认任务边界和运行基础。

### SOP / 业务规则

执行前先确认评论采集口径和交付要求。

当前口径：

- 时间范围：近一个月
- 评级：全部
- 评论类型：全部
- 排序：最新评价
- 地区：美国
- 输出格式：Excel xlsx
- 输出要求：保留评论明细，并生成评论分析汇总

### App 清单与链接

App 清单维护在 `review_check_v2.py` 的 `APP_CONFIGS` 中。

每个 App 配置包含：

- App 名称
- 七麦评论详情页链接

链接需要固定为美国区评论页，URL 中应包含：

```text
/country/us
```

### 运行环境

当前项目使用 Python 本地自动化方案。

核心依赖：

- `Playwright`：控制浏览器打开七麦页面、设置筛选器、点击导出
- `openpyxl`：读取和生成 Excel 文件
- Python 标准库：处理路径、时间、CSV、日志和文件备份

安装命令：

```bash
python3 -m pip install playwright openpyxl
python3 -m playwright install chromium
```

### 登录态与缓存

七麦可能需要登录或验证，因此脚本默认打开可视化 Chromium。

登录态缓存文件：

```text
qimai_storage_state.json
```

首次运行时，如页面要求登录，需要在浏览器中手动完成登录。登录成功后，脚本会保存状态，后续运行会优先复用该缓存。

## 二、自动化采集与数据处理主链路

这一阶段对应流程图第二行，是项目的核心执行链路。

### 遍历 App

脚本读取 `APP_CONFIGS`，按顺序逐个打开 App 的七麦评论链接。

执行策略：

- 单个 App 失败时记录错误
- 尽量继续处理后续 App
- 保留终端日志，便于定位失败节点

### 设置筛选器

进入评论页后，脚本设置基础评论筛选器。

筛选内容：

- 评级：全部
- 评论类型：全部
- 排序：最新评价

这些筛选器通过页面文本和可见元素定位完成。如果七麦页面结构变化，需要优先检查筛选器点击逻辑。

### 时间与地区

脚本继续设置时间和地区口径。

筛选内容：

- 日期：近一个月
- 地区：美国

地区同时通过 URL 中的 `/country/us` 进行校验。若页面未能自动点击地区筛选器，应检查七麦页面是否隐藏了地区控件，或是否已经由链接默认切到美国区。

### 导出数据

筛选器设置完成后，脚本点击七麦页面中的“导出数据”按钮。

导出逻辑：

- 定位可见导出按钮
- 监听浏览器下载事件
- 常规点击失败时使用 JS 兜底点击
- 下载超时或失败时输出诊断信息

### 保存原始表

每个 App 的原始导出文件都会保存到：

```text
qimai_downloads/
```

保存规则：

- 文件名前加 App 名称前缀
- 避免多个 App 的导出文件互相覆盖
- 保留原始表作为后续复查证据

### 解析与规范化

脚本读取七麦导出的 `xlsx` 或 `csv` 文件，并映射成统一字段。

处理内容：

- 识别导出表表头
- 映射评论时间、用户名、评级、标题、评论内容
- 清洗空白字符和异常文本
- 去重
- 为每个 App 工作表生成从 1 开始递增的 `review_id`

## 异常处理与诊断输出

流程图第二行下方包含两类辅助链路。

### 异常处理

需要重点处理的异常包括：

- 登录 / 验证失败
- 下载失败
- 导出空表
- 解析失败

处理原则：

- 优先保留现场信息
- 单个 App 异常不影响整体任务继续
- 必要时手动完成七麦登录或验证后重跑

### 诊断输出

项目中的常见诊断文件包括：

```text
qimai_export_debug.txt
qimai_debug_*_low_count.txt
```

这些文件用于检查：

- 页面是否成功加载
- 评论数量是否异常偏少
- 导出按钮是否可见
- 下载事件是否被触发
- 原始导出表是否为空

## 三、Excel 交付与复盘分析

这一阶段对应流程图第三行，用于生成最终可读、可复盘的 Excel 文件。

### 按 App 建工作表

脚本会为每个 App 建立一个独立 Sheet。

每个 App 明细表包含：

- `review_id`
- `评论时间`
- `用户名`
- `评级`
- `标题`
- `评论内容`
- `评论内容翻译`

其中 `review_id` 在每个 App 工作表内从 1 开始递增。

### 评论内容翻译

当前版本暂不执行自动翻译。

处理方式：

- 保留 `评论内容翻译` 字段
- 字段内容置空
- 后续如需翻译，可在该字段中写入本地或免费翻译结果

### 评论分析 Sheet

`review_data.xlsx` 中会新增一个名为：

```text
评论分析
```

的工作表。

该工作表包含：

- `app名称`
- `好评主要原因`
- `差评主要原因`

分析要求：

- 汇总每个 App 的好评主要原因
- 汇总每个 App 的差评主要原因
- 每个原因小点都标注对应 `review_id`
- 用户可根据 `review_id` 回到 App 明细表复核原始评论

### 交互与验收

Excel 输出需要便于用户快速查阅。

当前交互和格式要求：

- `评论分析` 工作表中的 App 名称可跳转到对应 App Sheet
- App 名称跳转使用 Excel 内部链接公式
- 冻结首行
- 开启筛选
- 设置合理列宽
- 生成新文件前备份旧版 `review_data.xlsx`

内部跳转公式示例：

```text
=HYPERLINK("#'工作表名'!A1","App 名称")
```

不要使用外部文件路径形式的超链接，否则部分 Excel 环境会提示“无法打开指定的文件”。

## 验收标准

对照流程图，交付前需要确认：

- 已按 SOP 口径设置筛选器
- 已遍历 `APP_CONFIGS` 中的 App
- `qimai_downloads/` 中存在原始导出文件
- 已生成 `review_data.xlsx`
- `评论分析` 工作表存在

## 后续扩展方向

### 新增 App

在 `review_check_v2.py` 的 `APP_CONFIGS` 中新增配置即可。

需要确认：

- App 名称适合用作 Excel Sheet 名
- 七麦链接为评论详情页
- URL 地区为美国区 `/country/us`

### 增加翻译

当前流程只预留翻译字段。如需启用翻译，建议：

- 优先使用本地或免费库
- 翻译失败时保留空值
- 不影响评论明细和分析表生成

### 优化评论分析

当前评论分析以本地规则和评论证据为基础。后续可以继续扩充：

- 价格 / 订阅问题
- 功能体验
- 识别准确率
- 稳定性和 Bug
- 广告或付费墙
- 食物数据库和营养记录
- 客服和开发者回复

所有分析点都应保留 `review_id` 证据，避免只给结论无法追溯。
